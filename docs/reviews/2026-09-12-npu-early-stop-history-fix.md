# PR #2599 早期停止と短い履歴保持の追加修正

## 変更理由

実機で送信直後の停止後に空のPENDING応答行が残った。応答の挿入がコミットされてから呼び出し側へIDが返るまでにキャンセルされると、UIが行IDを取得できないまま後処理に進む可能性がある。

応答行の挿入とIDの取得だけをNonCancellableで実行し、外側に取得済みIDを保持する。キャンセルの伝達後はその行をNonCancellableでCANCELLEDに移し、元のCancellationExceptionを再送出する。開始前のキャンセルは挿入前に拒否する。推論自体はNonCancellableにしていない。

## 履歴予算

固定に近い256の出力予約を先に差し引くため、短い直前の会話さえ除外されていた。最低128の出力余地を確保しながら直近の完全なユーザー・モデルのペアを選択し、その後の空き容量から出力予約を最大256まで増やす。

これは推定による入力判定であり、実際のトークン数やネイティブ出力上限ではない。保持しきれない古い会話を除外する方針と現在の質問を切り詰めない方針は維持する。

## 検証

Standard DebugのNPU・AssistantMessageLifecycle関連447テスト、失敗0。アプリ本体コンパイル成功、git diff --check成功。

追加ケース:
- 挿入コミット後・ID返却前のキャンセルで同じ行がCANCELLEDになる。
- GENERATINGへの更新待ちのキャンセルでPENDINGを残さない。
- 既にキャンセルされた呼び出しは行を作らない。
- キャンセルした行への遅いcheckpointは失敗し、新規の応答行は正常に開始できる。
- 名前を伝えた短い会話と、実機で使用した短い算術会話のペアを予算内に保持する。

実機での早期停止・名前の想起は未検証。過去に残った検証用PENDING行の削除や通常アプリの更新は実施していない。4+5の誤答、TTS二重要求、GPU逐次表示の修正は含めない。
