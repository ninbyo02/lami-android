# 日本語・単一話者TTSのPC試作とSM8750事前コンパイル

続報: [ラミィ声の短期学習試験と再検証](2026-10-28-tts-lite-voice-trials.md)。以下は前段の記録。
これは最初の試作時点の記録である。後続の[分割合成と学習準備の結果](2026-10-28-tts-lite-chunking.md)も参照する。

日本語版MeloTTSをPCで動かし、Open JTalkによる読みの補助、固定長波形生成モデルのONNX化、
SM8750向けFP16 HTPキャッシュのオフライン生成まで確認した。
現時点の声は上流のJP話者で、ラミィの正本音声を学習したモデルではない。
実機でのHTP実行、音声品質の聴取、Androidへの組み込みは未検証である。

## 実施内容

- `experiment/japanese-tts-lite-20261028`を`main@166122318946`から作成した独立作業。
- 比較用に上流MeloTTS日本語モデルを8文×2回、読み補助版を16文×2回生成した。
- 前処理・ニューラル推論・PCM完成・初期化を分け、入力文・読み・音声ハッシュを保存した。
- 初回の文と、同じ文の繰り返しによるCPUキャッシュ効果を分けて報告する。
- 波形生成モデルだけを32潜在フレームに固定し、ONNX→QAIRT→SM8750 HTPキャッシュへ変換した。
- アプリの動作を切り替える変更は含まない。

## 結果

| 確認項目 | 結果 | 範囲 |
|---|---|---|
| 読み補助版の日本語生成 | 32/32成功 | 有限・非無音・非クリップのPCM。発音の全面合格を意味しない |
| 自動テスト | 6/6成功 | 計測境界、無効音声排除、読みの回帰 |
| 同文繰り返しのRTF中央値 | 約0.127 | PC CPU・4スレッド。実機NPUへ外挿しない |
| 初回の各文のRTF中央値 | 約0.587 | 最初の発話を除く15文。繰り返しの数値と区別する |
| ONNX波形出力 | 最大絶対誤差約7.97e-7 | 日本語発話由来の32フレーム、PyTorch FP32との比較 |
| SM8750用HTPキャッシュ | 生成成功、30,638,080 bytes | QAIRT 2.46、FP16、VTCM 8MB、波形生成部分のみ |
| NPU実行速度・消費電力 | 未検証 | NX733Jでの実行が必要 |

ONNXの対象は`[1,192,32]`の潜在表現から`[1,1,16384]`のPCMを作る部分である。
44.1kHz換算で約371.5msの音声に相当するが、これだけでは連続ストリーミングは成立しない。
HTPキャッシュのSHA256や全工程の終了コードは[qnn-sm8750.json](2026-10-28-tts-lite/qnn-sm8750.json)に記録した。

## 日本語の読みで分かったこと

上流の日本語前処理では、次の問題が実際に出た。

| 入力例 | 上流の前処理 | Open JTalkを先に通した結果 |
|---|---|---|
| 今日は…六時… | コンニチハ…ロクトキ… | キョーワ…ロクジ… |
| 百三 | ヒャクゾウ | ヒャクサン |
| USB…Android… | 英字部分が落ちる | ユーエスビー…アンドロイド… |

この違いを入力から追えるよう、全要求の`reading_input`と`normalized_text`を保存する。
Open JTalkの読みをMeloTTSの既存音素化へ渡しており、独自の日本語解析器は作っていない。
句読点・間・抑揚や未知の固有名詞は引き続き聴取と追加評価が必要である。

## 今回まだ確定していないこと

- PCM完成時間は全文合成の完了であり、「最初に音が聞こえるまで」の時間ではない。
- PCのカーネルキャッシュ、負荷、メモリ使用量は端末の推論条件と異なる。
- FP32 ONNX一致から、HTP FP16の波形一致や声質を結論しない。
- デコーダの前後文脈を含むチャンク分割、音響モデルの分割、全体のNPU配置は未実装。
- ラミィの声の学習、LamiVoiceEngineへの接続、停止・再生・LLM並行実行の確認は次工程。

## 次工程

まず音響モデルと波形生成を分け、チャンク境界でのPCM一致を確認する。
読みの評価と並行して、正本`lami-cute-v3-03`および人が承認した既存音声データから、
軽量な単一話者モデルへの声の学習を準備する。Chronicleの音声と未承認データは使わない。

端末が使える段階で、同じ入力に対するCPU／HTPの出力と速度、可聴再生開始、アンダーラン、
LLM同時動作時のメモリ・発熱・消費電力を確認する。それまではNPUでの超低遅延達成とは扱わない。
