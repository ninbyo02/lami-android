# NPU連続会話の予算管理修正

長文のNPU応答後に同じチャットで短い質問を送ると、保持されたConversationの履歴が設定上限512に達し、推論に失敗していました。出力上限32という診断値も生成後の計算であり、実際のConversation APIには適用されていませんでした。

このPRではエンジンを保持しつつ、会話を予算内の履歴からターンごとに再構築します。直近の完全なユーザー・モデルのペアを保持し、現在の質問は切り詰めません。質問だけで予算を超える場合は明示的な失敗理由を返して既存のフォールバック処理へ渡します。

- 入力見積もり、テンプレート余裕、出力予約、保持履歴数を記録。
- 推定値を正確なトークン数とは扱わず、出力予約をネイティブの生成上限とは扱わない。
- 生成後の短文判定による32という値を外し、設定された総容量512を上限値として記録。
- ロック取得後・会話生成前・推論完了後にキャンセルを確認。停止済みの同期応答を成功保存せず、既存のキャンセル・破棄経路へ進む。

検証: Standard DebugのNPU関連416テスト、失敗0。新規5テストで長文履歴の除去、直近ペアの保持、過大入力、孤立ターン、Unicodeを確認。アプリ本体のコンパイル成功。

制約: 正確なトークナイザー予算ではなく推定による入場制御です。会話再構築による履歴の減少とプリフィル時間増加があり得ます。ネイティブ停止完了の測定、実機の長文→短文→停止→再送信は未実施。TTS二重要求とGPU逐次表示は別の修正です。ネイティブライブラリは変更していません。

PR #2597を前提とする差分です。実機評価記録はPR #2598参照。端末へのインストール・マージは行っていません。
