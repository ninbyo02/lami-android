# BRAVIA テレビ操作ツール

KJ-55A9Fで確認したローカルネットワークのScalarWebAPI / IRCCを使う。
Androidの設定画面でテレビを検出・登録し、チャットの明確なテレビ操作依頼を、
ローカル・サーバーの推論モデル選択に依存せず処理する。
結果は会話へ保存し、TTSが有効なら既存の音声経路で読み上げる。

## 登録

1. テレビとスマートフォンを同じホームネットワークに接続する。
2. ラミィの「設定 → テレビ操作」で「テレビを探す」を押すか、テレビのIPv4アドレスを入力する。
3. 「テレビに認証番号を表示」を押し、テレビ画面の4桁の番号を入力して「登録する」を押す。
4. 「接続と対応操作を確認」で、そのテレビの操作キーと起動可能なアプリ名を取得する。
5. ネットワークから電源オンも使う場合は、テレビ側の「設定 → ネットワークとインターネット → リモートスタート」を有効にする。
   「モバイル機器設定 → リモートコントロール機能」も有効にする。

初回認証のPINは保存しない。返却されたCookieをAndroid Keystoreで暗号化して、
バックアップ対象外のアプリ専用領域に保存する。「接続情報を削除」はこの端末の保存情報を削除する。
テレビ側の登録機器の削除は、テレビのモバイル機器設定で行える。

## 操作例とツール

| 依頼例 | ツール |
|---|---|
| テレビの状態を教えて | tv_status |
| テレビをつけて／消して | tv_power |
| テレビの音量を10にして | tv_volume |
| テレビをミュートして | tv_mute |
| テレビをHDMI1に切り替えて | tv_input |
| テレビを地デジの1チャンネルにして | tv_channel |
| テレビで一時停止して／ホームに戻して | tv_key |
| テレビでYouTubeを開いて | tv_launch_app |

音量だけの依頼はスマートフォンやラミィ自身の音量と区別できないため、
「テレビの音量…」と指定する。引用・否定・複合依頼・将来の予定などは直接実行しない。
初版のチャット経路は定型的な日本語の明確な指示を認識する。
自由な言い換えをLLMで解釈する汎用の関数呼び出しループは、別途接続が必要。
BraviaToolCatalog.declarations()は関数定義を、BraviaManager.execute(BraviaToolCall)は
型と引数を検証する実行口を提供する。

チャンネルはテレビに登録されたボタン番号で指定する。「NHK」などの局名と番号の対応は推測しない。
放送切り替えキー・数字キーはテレビが返す実在するコードのみ使用する。
11・12番やアプリの起動可否は、認証後に取得するそのテレビの対応一覧による。
録画予約、外出先アクセス、番組検索・動画検索、サービスメニュー操作はこのツールの対象外。

## 操作結果

電源・音量・消音・HDMIは可能な範囲で状態を再取得する。
APIが受理したことと、現在の状態を確認できたことを別々に返す。
リモコン操作やアプリ起動で画面遷移を取得できない場合は「キー／起動要求を送った」と返す。
通信失敗時に変更操作を自動再送しない。電源オンが通信できない場合に限り、
認証時に取得したテレビのMACアドレスを対象にWake-on-LANを送る。

## 検証と制限

PC上のJUnitテストで初回認証、Cookie、型検証、誤認識の拒否、対応キーの照合、
SOAPエラー、数値の範囲、状態の読み戻し、変更操作の非再送を検証する。
実機で確認済みなのはKJ-55A9Fの機種情報・操作窓口の公開と、認証前アクセスの拒否まで。
認証と各操作の実機検証は、テレビ画面の認証番号を入力して登録した後に行う。

## PCから初回認証を確認する補助スクリプト

scripts/bravia_tv_setup.py begin --host <テレビのIPv4アドレス>
scripts/bravia_tv_setup.py complete

completeはテレビ画面のPINを標準入力から受け取り、認証後に機種・対応キー・音量API等を読み取る。
電源・チャンネルなどの変更操作は送らない。設定確認用のPCクライアントと、
Androidアプリのクライアントは独立しているため、スマートフォンではアプリの設定画面で登録する。
認証CookieはPC側の専用設定ディレクトリに所有者のみ読める権限で保存し、Gitには入れない。
