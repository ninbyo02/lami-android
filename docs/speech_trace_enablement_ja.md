# 診断収集の入口・容量制限
2026-10-15。

## 明示的な入口
debugのLamiNeuralChatVoiceFactory.createDiagnosticOrNull(context, modelArtifact, runtimeArtifact)を追加。
呼び出した時だけ、渡されたモデル/ランタイム実ファイルをSHA256化してtraceFactoryを接続する。
通常のcreateOrNullは変更せず、収集は既定で無効。UIの切替や端末への有効化操作は行っていない。

ハッシュ対象は呼び出し元が渡す2ファイル。実ロードされた全モデル・全ライブラリとの対応を保証しない。
モデル/ランタイムの選択・由来確認は診断側の責任。大量ファイルのハッシュはUIスレッド外で実行する。

## 保存上限
保存先: アプリ内部 diagnostics/speech_traces。
最大8件。各PCM4MiBまで、メタデータ16KiB未満。この収集部品が新規作成するデータの上限は合計約32MiB＋128KiB。
未完了ディレクトリも件数に含め、同時要求はプロセス内共通ロックとUUIDで保護する。
この領域へ他の処理が書いたファイル容量や別プロセスの書き込みは制御対象外。
既存ファイルの削除・上書きはしない。上限時は収集を無効化し発話を継続する。過大PCMは追加の保存用バッファを確保する前に拒否。

## 検証
ホストJVM22件・Python7件成功。未完了記録による上限、重複IDの分離、過大PCM拒否を検証。
Android Kotlinコンパイル結果はnpu-host-quota-android-compile-20261015.json参照。
現在の実機で新規収集を行った結果ではない。

## 次の段階
収集JSONをPCで検証・再生する読込部品を追加する。
要求ごとの終端記録、実ロードスタックとの由来照合、UI/診断サービス入口、エクスポートは未対応。SIGABRTの再現・修正を達成したものではない。
